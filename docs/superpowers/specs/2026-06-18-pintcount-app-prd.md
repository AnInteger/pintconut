> 版本：v1.1

## 0. 文档目的

将 Pintconut 从"开发者命令行 / 标注工具"**重新定位为面向消费者的移动端 APP「Pintcount」**。本文档定义产品定位、目标用户、核心功能、商业模式与路线图，作为后续 UI 设计与开发的依据。

**范围声明**：本文档只定义**产品（APP）本身**。仓库内既有的标注 / 训练工具属于**开发内部资产**，不纳入产品（详见第 11 节附录）。

---

## 1. 产品定位与价值主张（UVP）

### 1.1 一句话定位

**Pintcount 是拼豆的"熨烫前质检员"**：拍一张成品照，对照图纸，告诉用户哪里拼错了，避免"一熨定终身"的返工。

### 1.2 差异化

现有拼豆 APP（Beads Creator、颂拼豆、PerlerLab、七卡瓦底稿生成器、拼豆图纸创作等）**几乎全部聚焦"设计 / 生成图纸"**，没有一款主打"校验成品"。Pintcount 占据这个空白定位：

> **别人帮你设计，Pintcount 帮你不翻车。**

### 1.3 为什么是现在

- 拼豆在小红书 / 抖音呈爆发式增长（百亿级浏览量），"翻车求医""图纸分享"是高频内容，用户基数与活跃度都在快速上升。
- 用户核对成品目前**完全依赖肉眼**：拼大图时根本看不过来，且熨烫后才发现错误只能整件重做。这个**"不可逆时刻"的痛点真实存在，且未被任何产品化工具解决**。

### 1.4 核心价值三件套

| 维度 | 价值 |
|------|------|
| **准** | LAB 色彩空间逐格比对 + 端侧 CV，可靠标注每一处错误（颜色错 / 空缺 / 多余）。 |
| **快** | 一键拍照即出结果，不挡手、不打断创作节奏。 |
| **安心** | 照片全程不出手机，零服务器成本，隐私无忧。 |

## 2. 市场背景与竞品

| 竞品（代表性） | 定位 | 是否做"成品校验" |
|----------------|------|------------------|
| 拼豆图案设计（Beads Creator） | 像素编辑器，设计图纸 | ❌ |
| 颂拼豆 | 照片 → 像素图纸 + 色号统计 | ❌ |
| PerlerLab / 七卡瓦底稿生成器 | AI 图片转图纸 | ❌ |
| 拼豆图纸创作 | 像素绘画 + 工艺流程管理 | ❌ |

**结论**：赛道拥挤，但全部挤在"设计 / 生成"侧。"**校验成品**"是一块明确的空白，且与社交分享天然契合（"看我质检满分""终于不翻车了"）。Pintcount 不与设计工具正面对抗，而是**补全创作流程中缺失的"质检"环节**。

## 3. 目标用户与核心场景

### 3.1 目标用户

| 画像 | 特征 | 核心痛点 |
|------|------|----------|
| **跟图新手**（主力） | 照小红书 / 抖音图纸拼，经验少 | 最容易拼错；肉眼核对累且易漏；熨烫后才发觉，重做成本高 |
| **进阶玩家** | 拼大图 / 复杂图，几百上千颗豆 | 肉眼根本查不过来，需要逐格核对 |

### 3.2 核心场景（Jobs-To-Be-Done）

> "我拼到一半 / 拼完了，**烫之前**，快速知道有没有错、错在哪、怎么改。"

关键时机：**熨烫之前**。一旦熨烫，豆子永久熔合、不可逆。这是 Pintcount 创造价值的唯一时刻。

## 4. 核心功能

Pintcount 的核心是**一条一体化的魔法流**：选图纸 → 拍成品照 → 自动检测 → 看差异。图纸与拍照不是两个独立功能，而是这条流的先后两步——**必须先有图纸作为对照基准，再拍成品照检测**。围绕这条流，MVP 做以下几件事（全部端侧完成、无账号、无后端）。

> **核心难点在"检测"，不在"图纸"。** 真正难的是从一张实物成品照里可靠还原每一格的真实颜色（光照、角度、反光、拼板多样性都会干扰）；图纸本身多为规整数字方阵，解析相对容易。检测准确性是产品价值的根基（见 §10 风险），也是后续持续迭代的主战场。

### 4.1 核心流程：选图纸 → 拍照 → 自动检测

**第一步 · 选图纸（对照基准）**

- 图纸只作为本次检测的对照基准，**用完即弃**，不提供图纸库 / 管理能力。
- 来源（4 条路径）：

  | 入口 | 说明 | 优先级 |
  |------|------|--------|
  | **相册导入** | 从小红书 / 抖音截图、相册图纸图直接选取 | 主路径 |
  | **拍照** | 拍纸质图纸（需做去 glare / 透视处理） | 次 |
  | **分享扩展**（Share Extension） | 在微信 / 小红书 / 文件里对图片选"用 Pintcount 打开"，直接进入比对 | **最顺滑的获客入口** |
  | **文件导入** | Files App / iCloud | 辅助 |

- **多品牌色盘**：内置主流色盘预设 Perler / Hama / Artkal 等（色盘只是"颜色 → 名称"查询表，与匹配算法无关）。首次使用选一次品牌，后续默认沿用，可在设置切换。**自定义色盘（用户自建色号表）放 v2**。
- **图纸自动解析**：识别有效网格区域（裁掉边距 / 水印 / 作者署名）、识别行列数（网格规格）、逐格取色映射到所选色盘。
- 图纸随对应"作品"保留，**后续对该作品重扫无需重复导入图纸**（图纸只是作品记录的一部分，不构成独立的图纸管理界面）。

**第二步 · 拍成品照 → 自动检测**

- **输入**：相机拍照 或 从相册选成品照。
- **流程**：一键自动执行检测：定位拼板 → 校正视角 → 逐格读取颜色 → 与图纸逐格比对 → 出结果。
- **零手动干预**：不调角点、不填尺寸（拼板尺寸从检测结果自动推断，并与图纸网格自动对齐）。

### 4.2 差异结果：告诉用户哪里错了（内容）

检测结果要清晰告诉用户**有哪些差异**，便于逐处修正。差异分三类：

| 类型 | 含义 | 需要给出的信息 |
|------|------|----------------|
| **颜色错** | 图纸要求 A 色，实际是 B 色 | 位置、应有色、实际色 |
| **空缺** | 图纸要求有豆，实际没放 | 位置 |
| **多余** | 图纸要求空，实际放了豆 | 位置 |

- 结果要**可定位、可计数**（如"共 3 处：2 颜色错 + 1 空缺"），支持用户逐项核对与修正。
- 具体的视觉呈现与标注方式（红框、图标、布局等）由**原型设计**决定，不在 PRD 范围。更具创意的结果展示形式（如对照叠加、逐项导航等）留待原型设计阶段探索。

### 4.3 分享卡片（增长引擎）

- 检测完成后一键生成**分享卡片**：成品缩略图 + 错误数 + 结论（如"质检通过 ✓" / "发现 3 处错误"）+ **"用 Pintcount 一键质检"品牌水印**（含小红书 / 抖音可识别的品牌标记）。
- 调用**系统分享表单**（Share Sheet）发到任意平台——卡片本身就是**免费广告**，构成"检测 → 分享 → 拉新"闭环。
- 除分享卡片外，用户也可直接把**成品照原图**经系统分享发出（"保留照片 → 分享照片"两条路都通）。
- MVP 固定一种卡片模板；多模板放 v2。

### 4.4 个人作品库与重扫

- 本地保存"作品"：**用户的成品照 + 历次检测记录 + 结果缩略图**（图纸作为作品记录的一部分一并保留，便于重扫）。
- **照片保留**：成品照与检测结果一同留在作品库，可随时回看，也可存入系统相册。
- 支持同一作品**多次重扫**（改完豆子后复核），形成"检测 → 修正 → 复核"闭环。
- 纯本地存储（App sandbox），**不上云**。

### 4.5 失败兜底（魔法优先，反复失败才出手动逃生舱）

整条魔法流遵循同一原则——默认全自动，不让用户手动调参：

1. 置信度低 → 温和提示重试（重选图纸 / 重新截图 / 重拍 / 调整打光与角度），**不弹手动工具**。
2. **反复失败** → 才提供**唯一一项**手动逃生舱（图纸：手动框选网格区；拍照：重拍引导），避免死循环与无助感。
3. 全程守住"魔法感"，不为兜底牺牲体验。

## 5. 信息架构与用户流程

### 5.1 信息架构（极简三屏）

```
[ 首页 ]                 [ 作品库 ]              [ 设置 ]
  一键拍照入口              本地作品列表             色盘品牌选择
  选图纸 / 选相册           每作品 → 成品照 + 历次检测   关于 / 隐私说明
  (开 App 即用)            重扫复核
```

**首页 = 拍照入口**，开 App 即用，零学习成本。

### 5.2 核心用户流程

```
打开 App
   │
[首页] ── 选图纸 ──→ 相册 / 拍照 / 分享扩展 / 文件
   │                     │
   │                (自动解析图纸：网格区域 + 行列数 + 色盘)
   │                     │
   └── 拍照 / 选成品照 ──→ 【一键自动检测】(定位 → 校正 → 逐格读取 → 比对)
                               │
                          [差异结果] 错误清单 + 计数（呈现方式见原型设计）
                               │
                ┌──────────────┼──────────────┐
             重扫复核       生成分享卡片      保存到作品库
        (改完豆子再扫)     (带水印，系统分享)   (本地，可多次复核)
```

## 6. 数据与隐私（卖点，非负担）

- 照片、图纸、作品记录**全本地存储**（App sandbox + 相册写入），**不收集、不上传任何用户数据**。
- **权限最小化**：相机、照片库，仅说明用途后请求。
- **分享卡片**由用户主动触发，经**系统分享**分发，不经任何自有服务器。
- **隐私无忧**既是用户信任的基础（"防翻车"工具必须可信），也是 App Store 审核加分项与对外宣传点。

---

## 7. 商业模式

- **MVP 全免费、无内购**（零后端成本，可持续）。
- 增长靠**水印**：分享卡片 = 免费广告，形成自传播闭环。
- **远期变现（v2+，不在 MVP）**：Pro 订阅（去水印、高清导出、批量检测、可选云备份）。

## 8. 成功指标（KPI）

| 维度 | 指标 |
|------|------|
| **北极星** | 月活质检次数（核心价值被使用的频次） |
| **传播** | 分享卡片生成数；水印带来的新增安装（归因估算） |
| **留存** | 次日 / 7 日 / 30 日留存；**"重扫"行为率**（体现质检闭环价值） |
| **体验** | 一次检测成功率；端到端耗时 P50 / P95 |
| **准确** | 误报率 / 漏报率（抽测，决定"防翻车"信任度） |

## 9. MVP 范围与路线图

### 9.1 v1（MVP）

- 核心流程（选图纸 → 拍照 → 检测）、差异结果、分享卡片、作品库全部上线。
- 2–3 个主流色盘预设（Perler / Artkal 等）。
- 移动端，免费 + 水印。
- 单一分享卡片模板。

### 9.2 v2

- 完整多品牌色盘 + **自定义色盘**。
- 检测稳定性增强（更多场景数据迭代模型）。
- 作品库增强（分组、备注、历史对比）。
- 多分享卡片模板。
- **评估 Android**（Flutter 移植 or 双端原生，视用户分布决定）。

### 9.3 v3+

- Pro 订阅变现（去水印 / 高清 / 批量 / 云备份）。
- （可选）图纸社区——但**质检始终是核心**，社区是延伸而非替代。

## 10. 风险与开放问题

| 风险 | 影响 | 缓解 |
|------|------|------|
| 检测准确性 / 稳定性（光照 / 角度 / 反光 / 拼板多样性） | 误报漏报、检测失败 | 用现有标注工具**持续采集数据迭代模型**；失败兜底与重拍引导 |
| 图纸解析鲁棒性（截图 / 拍照 / 水印 / 非标网格） | 基准错误导致整次比对失真 | 自动解析 + 手动逃生舱；后续支持更多图纸格式 |
| 色彩准确性（品牌色差 + 拍照色温） | 误判颜色 | LAB 匹配 + 拍照白平衡提示 + 多色盘 |
| 一键魔法的失败体验 | 失败时用户无助 | 失败引导 + 逃生舱，折中而不破坏魔法感 |
| App 体积与运行性能（中低端机） | 体验差 | 控制资源占用，按机型分级体验 |
| 单人维护（算法 + 产品） | 进度风险 | MVP 聚焦；先用 Python 流水线验证算法再移植 |

**开放问题（待后续 UI 设计 / 技术预研解答）**：
1. 图纸网格区域的自动裁剪算法在移动端的鲁棒性，需技术预研（spike）。
2. 端侧检测在目标机型上的实际耗时与体积，需实测。
3. 分享卡片水印的设计规范（品牌标记、小红书 / 抖音可识别性）。

## 11. 附录：开发工具（**不纳入产品**）

仓库内既有的标注 / 训练工具是**开发内部资产**，用于持续训练与迭代端侧检测模型：

| 工具 | 用途 |
|------|------|
| `training/semi_auto_label.py` | FastSAM 半自动标注（终端） |
| `src/label_ui.py` | Gradio 标注 Web UI |
| `training/train.py` / `bead_train.py` | 模型训练 |
| `training/validate.py` / `bead_validate.py` | 模型验证 |
| `training/collect_helper.py` | 照片批量整理 |

- 这些工具产出**新的检测模型**，通过 **App 发版**更新到用户设备。
- **不会出现在产品 APP 中**，无用户界面。
- 仅在仓库内文档化，供开发自用。

## 12. 关键决策记录

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 产品定位 | **纯质检工具**（不碰设计 / 编辑） | 赛道拥挤在设计侧，质检是空白；MVP 最快 |
| 2 | 检测架构 | **端侧、无后端** | 零服务器成本、隐私好、可离线，匹配纯工具定位 |
| 3 | 社交实现 | **本地优先 + 系统分享**（无后端） | 整个 MVP 完全无服务器，零成本可持续 |
| 4 | 平台 | **移动端优先（平台与技术栈后续评估）** | 检测算法已在 Python 原型验证；移动端覆盖核心用户，平台与技术细节延后 |
| 5 | 商业模式 | **免费上线 + 水印增长** | 零成本可承受；社交传播驱动获客，契合拼豆生态 |
| 6 | 核心交互 | **一键魔法流（A）** | 最少步骤、最魔法；失败时引导 + 逃生舱兜底 |
| 7 | 色盘（MVP） | **内置 2–3 主流预设**，自定义放 v2 | 色盘是查表、成本低但对"准"价值大 |
| 8 | 图纸失败兜底 | **魔法优先，反复失败才出手动逃生舱** | 保持魔法感的同时避免死循环 |
