# Pintcount — 拼豆质检 APP 产品需求文档（PRD）

> 日期：2026-06-18
> 状态：草案（待评审）
> 版本：v1.0
> 文档类型：产品需求文档（Product Requirements Document）
> 产品形态：移动端 APP（iOS 优先）
> 关联：本 PRD 重新定义项目产品方向。技术原型见现有 `pintconut` 仓库（已跑通的 Python CV 流水线：拼板定位 → 透视校正 → 网格提取 → LAB 颜色对比 → 差异标注）。

---

## 0. 文档目的

将 Pintconut 从"开发者命令行 / 标注工具"**重新定位为面向消费者的移动端 APP「Pintcount」**。本文档定义产品定位、目标用户、核心功能、技术架构、商业模式与路线图，作为后续 UI 设计与开发的依据。

**范围声明**：本文档只定义**产品（APP）本身**。仓库内既有的标注 / 训练工具属于**开发内部资产**，不纳入产品（详见第 12 节附录）。

---

## 1. 产品定位与价值主张（UVP）

### 1.1 一句话定位

**Pintcount 是拼豆的"熨烫前质检员"**：拍一张成品照，对照图纸，告诉用户哪里拼错了，避免"一熨定终身"的返工。

### 1.2 差异化

现有拼豆 APP（Beads Creator、颂拼豆、PerlerLab、七卡瓦底稿生成器、拼豆图纸创作等）**几乎全部聚焦"设计 / 生成图纸"**，没有一款主打"校验成品"。Pintcount 占据这个空白定位：

> **别人帮你设计，Pintcount 帮你不翻车。**

### 1.3 为什么是现在

- 拼豆在小红书 / 抖音呈爆发式增长（百亿级浏览量），"翻车求医""图纸分享"是高频内容，用户基数与活跃度都在快速上升。
- 用户核对成品目前**完全依赖肉眼**：拼大图时根本看不过来，且熨烫后才发现错误只能整件重做。这个**"不可逆时刻"的痛点真实存在，且未被任何产品化工具解决**。

### 1.4 核心价值三件套

| 维度 | 价值 |
|------|------|
| **准** | LAB 色彩空间逐格比对 + 端侧 CV，可靠标注每一处错误（颜色错 / 空缺 / 多余）。 |
| **快** | 一键拍照即出结果，不挡手、不打断创作节奏。 |
| **安心** | 照片全程不出手机，零服务器成本，隐私无忧。 |

## 2. 市场背景与竞品

| 竞品（代表性） | 定位 | 是否做"成品校验" |
|----------------|------|------------------|
| 拼豆图案设计（Beads Creator） | 像素编辑器，设计图纸 | ❌ |
| 颂拼豆 | 照片 → 像素图纸 + 色号统计 | ❌ |
| PerlerLab / 七卡瓦底稿生成器 | AI 图片转图纸 | ❌ |
| 拼豆图纸创作 | 像素绘画 + 工艺流程管理 | ❌ |

**结论**：赛道拥挤，但全部挤在"设计 / 生成"侧。"**校验成品**"是一块明确的空白，且与社交分享天然契合（"看我质检满分""终于不翻车了"）。Pintcount 不与设计工具正面对抗，而是**补全创作流程中缺失的"质检"环节**。

## 3. 目标用户与核心场景

### 3.1 目标用户

| 画像 | 特征 | 核心痛点 |
|------|------|----------|
| **跟图新手**（主力） | 照小红书 / 抖音图纸拼，经验少 | 最容易拼错；肉眼核对累且易漏；熨烫后才发觉，重做成本高 |
| **进阶玩家** | 拼大图 / 复杂图，几百上千颗豆 | 肉眼根本查不过来，需要逐格核对 |
| **接单手作人** | 给客户定制，需交付质量 | 错一颗可能整单返工，质检是刚需 |

### 3.2 核心场景（Jobs-To-Be-Done）

> "我拼到一半 / 拼完了，**烫之前**，快速知道有没有错、错在哪、怎么改。"

关键时机：**熨烫之前**。一旦熨烫，豆子永久熔合、不可逆。这是 Pintcount 创造价值的唯一时刻。

## 4. 核心功能需求（MVP）

> 全部**端侧**完成，**无账号、无后端**。MVP 只做以下五件事。

### 4.1 功能总览

| 编号 | 功能 | 一句话描述 |
|------|------|-----------|
| **F1** | 图纸上传与管理 | 导入图纸图片，自动解析网格与颜色，作为比对基准 |
| **F2** | 一键拍照检测 | 拍 / 选成品照，一键自动跑完整比对流水线 |
| **F3** | 差异结果展示 | 在成品照上红框标注每一处错误，并给出错误清单 |
| **F4** | 分享卡片 | 一键生成带品牌水印的分享图，经系统分享分发 |
| **F5** | 个人作品库 | 本地保存作品（图纸 + 历次检测），支持重扫复核 |

---

### 4.2 F1 · 图纸上传与管理 ⭐（核心难点，重点设计）

图纸是比对的基准。它的来源杂、质量参差，是整个体验成败的关键。

#### 4.2.1 入口（4 条路径）

| 入口 | 说明 | 优先级 |
|------|------|--------|
| **相册导入** | 从小红书 / 抖音截图、相册图纸图直接选取 | 主路径 |
| **拍照** | 拍纸质图纸（需做去 glare / 透视处理） | 次 |
| **分享扩展**（Share Extension） | 在微信 / 小红书 / 文件里对图片选"用 Pintcount 打开"，直接进入比对 | **最顺滑的获客入口** |
| **文件导入** | Files App / iCloud | 辅助 |

#### 4.2.2 自动解析（核心算法难点）

1. **网格区域识别**：自动识别图纸的有效网格区域，裁掉边距 / 水印 / 作者署名（复用现有边缘检测与网格推断思路）。
2. **尺寸识别**：自动识别图纸的行列数（网格规格）。
3. **颜色提取**：逐格提取颜色 → 映射到所选色盘。

#### 4.2.3 多品牌色盘

- 内置主流色盘预设：**Perler / Hama / Artkal** 等（LAB 匹配本身与色盘无关，色盘只是"颜色 → 名称"的查询表）。
- 用户**首次使用时选一次品牌**即可，后续默认沿用，可在设置中切换。
- **自定义色盘（用户自建色号表）放 v2**，不在 MVP。

#### 4.2.4 失败兜底（魔法优先，反复失败才出手动逃生舱）

- 默认全自动解析，**不让用户手动调四角**，保持"魔法感"。
- 解析置信度低时：提示"图纸不太清晰，建议重选一张 / 重新截图"。
- **反复失败**时：提供"手动框选网格区"作为逃生舱（仅此一项手动干预），避免死循环。

#### 4.2.5 图纸与作品绑定

- 图纸导入后与一个"作品"绑定，**后续重扫同一作品无需重复导入图纸**。

---

### 4.3 F2 · 一键拍照检测（魔法流）

- **输入**：相机拍照 或 从相册选择成品照。
- **流程**：一键自动执行 → 拼板定位 → 透视校正 → 网格提取 → LAB 颜色对比 → 出结果。
- **零手动干预**：不调角点、不填尺寸（拼板尺寸从检测结果自动推断，并与图纸网格自动对齐）。
- **失败兜底**：识别困难时给出"重拍 + 打光 / 角度建议"，**而非强制手动校正**，守住魔法流体验。

### 4.4 F3 · 差异结果展示

- 在成品照上用**红框标注**每一处错误格（沿用现有 `compare.py` 能力）。
- **三类错误分类**：
  - 🔴 **颜色错**（应有 A 色，实际是 B 色）
  - ⬜ **空缺**（图纸要求有豆，实际没放）
  - ➕ **多余**（图纸要求空，实际放了豆）
- **错误清单**：可点击定位、可计数（如"共 3 处错误：2 颜色错 + 1 空缺"）。
- 成品图可缩放查看细节，一目了然。

### 4.5 F4 · 分享卡片（增长引擎）

- 检测完成后一键生成**分享卡片**：成品缩略图 + 错误数 + 结论（如"质检通过 ✓" / "发现 3 处错误"）+ **"用 Pintcount 一键质检"品牌水印**（含小红书 / 抖音可识别的品牌标记）。
- 调用**系统分享表单**（Share Sheet）发到任意平台——卡片本身就是**免费广告**，构成"检测 → 分享 → 拉新"闭环。
- MVP 固定一种卡片模板；多模板放 v2。

### 4.6 F5 · 个人作品库

- 本地保存"作品"（图纸 + 历次检测记录 + 缩略图）。
- 支持同一作品**多次重扫**（改完豆子后复核），形成"检测 → 修正 → 复核"闭环。
- 纯本地存储（App sandbox），**不上云**。

## 5. 信息架构与用户流程

### 5.1 信息架构（极简三屏）

```
[ 首页 ]                 [ 作品库 ]              [ 设置 ]
  一键拍照入口              本地作品列表             色盘品牌选择
  选图纸 / 选相册           每作品 → 图纸 + 历次检测   关于 / 隐私说明
  (开 App 即用)            重扫复核
```

**首页 = 拍照入口**，开 App 即用，零学习成本。

### 5.2 核心用户流程

```
打开 App
   │
[首页] ── 选图纸 ──→ 相册 / 拍照 / 分享扩展 / 文件
   │                     │
   │                (自动解析图纸：网格区域 + 行列数 + 色盘)
   │                     │
   └── 拍照 / 选成品照 ──→ 【一键自动比对】(定位→校正→网格→LAB对比)
                               │
                          [差异结果] 红框 + 错误清单 + 计数
                               │
                ┌──────────────┼──────────────┐
             重扫复核       生成分享卡片      保存到作品库
        (改完豆子再扫)     (带水印，系统分享)   (本地，可多次复核)
```

## 6. 技术架构（端侧 iOS 原生）

### 6.1 架构总览

```
            ┌──────────── CoreML（端侧，无后端）────────────┐
拍照/选图 → │ ① 拼板定位（YOLOv8-seg → 量化 .mlmodelc）       │ → 差异结果
图纸导入 → │ ② 透视校正 + 网格提取（Vision / Accelerate）    │
            │ ③ LAB 颜色匹配（纯 Swift 查表）                │
            │ ④ 图纸解析（同 ② 思路）                         │
            └───────────────────────────────────────────────┘
   所有资产（模型权重 / 色盘 JSON）打包进 App Bundle
```

### 6.2 模块映射（现有 Python → iOS）

| 现有模块 | iOS 实现 | 说明 |
|----------|----------|------|
| `detect.py`（YOLO 拼板定位） | CoreML 模型 | YOLOv8n-seg 导出量化 `.mlmodelc`，iPhone 推理 <1s |
| `grid.py`（透视校正 + 网格） | Vision + Accelerate（或 OpenCV.framework） | 几何变换是纯数学，Swift 可直接实现 |
| `color.py`（LAB 匹配） | Swift + Accelerate | LAB 转换 + 色盘查表 |
| `blueprint.py`（图纸解析） | 同 grid 思路 | 复用网格提取逻辑 |
| `compare.py`（差异标注） | SwiftUI / CoreGraphics | 红框覆盖绘制 |

### 6.3 性能目标

- **端到端检测耗时**：P50 ≤ 2s，P95 ≤ 3s。
- **一次检测成功率**（初版）：≥ 90%，随模型迭代持续提升。
- **App 体积**：控制模型量化后体积，避免拖累下载。

### 6.4 无后端

- 无 API、无数据库、无账号、无服务器。检测、解析、存储、分享全在端侧 + 系统 API 完成。

---

## 7. 数据与隐私（卖点，非负担）

- 照片、图纸、作品记录**全本地存储**（App sandbox + 相册写入），**不收集、不上传任何用户数据**。
- **权限最小化**：相机、照片库，仅说明用途后请求。
- **分享卡片**由用户主动触发，经**系统分享**分发，不经任何自有服务器。
- **隐私无忧**既是用户信任的基础（"防翻车"工具必须可信），也是 App Store 审核加分项与对外宣传点。

---

## 8. 商业模式

- **MVP 全免费、无内购**（零后端成本，可持续）。
- 增长靠**水印**：分享卡片 = 免费广告，形成自传播闭环。
- **远期变现（v2+，不在 MVP）**：Pro 订阅（去水印、高清导出、批量检测、可选云备份）。

## 9. 成功指标（KPI）

| 维度 | 指标 |
|------|------|
| **北极星** | 月活质检次数（核心价值被使用的频次） |
| **传播** | 分享卡片生成数；水印带来的新增安装（归因估算） |

## 10. MVP 范围与路线图

### 10.1 v1（MVP）

- F1–F5 五大功能全部上线。
- 2–3 个主流色盘预设（Perler / Artkal 等）。
- iOS 端侧，免费 + 水印。
- 单一分享卡片模板。

### 10.2 v2

- 完整多品牌色盘 + **自定义色盘**。
- 检测稳定性增强（更多场景数据迭代模型）。
- 作品库增强（分组、备注、历史对比）。
- 多分享卡片模板。
- **评估 Android**（Flutter 移植 or 双端原生，视用户分布决定）。

### 10.3 v3+

- Pro 订阅变现（去水印 / 高清 / 批量 / 云备份）。
- （可选）图纸社区——但**质检始终是核心**，社区是延伸而非替代。

## 11. 风险与开放问题

| 风险 | 影响 | 缓解 |
|------|------|------|
| 端侧检测稳定性（光照 / 角度 / 反光 / 拼板多样性） | 误报漏报、检测失败 | 用现有标注工具**持续采集数据迭代模型**；失败兜底与重拍引导 |
| 图纸解析鲁棒性（截图 / 拍照 / 水印 / 非标网格） | 基准错误导致整次比对失真 | 自动解析 + 手动逃生舱；后续支持更多图纸格式 |
| 色彩准确性（品牌色差 + 拍照色温） | 误判颜色 | LAB 匹配 + 拍照白平衡提示 + 多色盘 |
| 一键魔法的失败体验 | 失败时用户无助 | 失败引导 + 逃生舱，折中而不破坏魔法感 |
| CoreML 模型体积 / 性能（中低端机） | 体验差 | YOLOv8n 量化导出，按机型分级 |
| 单人维护（端侧 ML + 原生） | 进度风险 | MVP 聚焦；先用 Python 流水线验证算法再移植 |

**开放问题（待后续 UI 设计 / 技术预研解答）**：
1. 图纸网格区域的自动裁剪算法在 iOS 端的鲁棒性，需技术预研（spike）。
2. CoreML 部署 YOLOv8n-seg 在目标机型上的实际耗时与体积，需实测。
3. 分享卡片水印的设计规范（品牌标记、小红书 / 抖音可识别性）。

## 12. 附录：开发工具（**不纳入产品**）

仓库内既有的标注 / 训练工具是**开发内部资产**，用于持续训练与迭代端侧检测模型：

| 工具 | 用途 |
|------|------|
| `training/semi_auto_label.py` | FastSAM 半自动标注（终端） |
| `src/label_ui.py` | Gradio 标注 Web UI |
| `training/train.py` / `bead_train.py` | 模型训练 |
| `training/validate.py` / `bead_validate.py` | 模型验证 |
| `training/collect_helper.py` | 照片批量整理 |

- 这些工具产出**新的 `.mlmodelc` 模型**，通过 **App 发版**更新到用户设备。
- **不会出现在产品 APP 中**，无用户界面。
- 仅在仓库内文档化，供开发自用。

## 13. 关键决策记录

| # | 决策点 | 选择 | 理由 |
|---|--------|------|------|
| 1 | 产品定位 | **纯质检工具**（不碰设计 / 编辑） | 赛道拥挤在设计侧，质检是空白；MVP 最快 |
| 2 | 检测架构 | **端侧 CoreML** | 零服务器成本、隐私好、可离线，匹配纯工具定位 |
| 3 | 社交实现 | **本地优先 + 系统分享**（无后端） | 整个 MVP 完全无服务器，零成本可持续 |
| 4 | 平台栈 | **iOS 原生（SwiftUI + CoreML）优先** | CoreML 对 YOLO 支持最顺滑，单平台 ML 最省心 |
| 5 | 商业模式 | **免费上线 + 水印增长** | 零成本可承受；社交传播驱动获客，契合拼豆生态 |
| 6 | 核心交互 | **一键魔法流（A）** | 最少步骤、最魔法；失败时引导 + 逃生舱兜底 |
| 7 | 色盘（MVP） | **内置 2–3 主流预设**，自定义放 v2 | 色盘是查表、成本低但对"准"价值大 |
| 8 | 图纸失败兜底 | **魔法优先，反复失败才出手动逃生舱** | 保持魔法感的同时避免死循环 |
