## User Scenarios & Testing *(mandatory)*

原型面向两类"用户"：① **评审者**（验证设计是否表达产品价值）；② **终端用户**（原型描绘其使用旅程）。以下故事按优先级排列，每个可独立评审。

### User Story 1 - 核心质检魔法流（Priority: P1）

描绘完整 happy path：首页 → 选图纸（自动解析 + 备豆统计 + 选色盘）→ 拍成品照 → 检测中 → 差异结果（多色标记三类错误 / 通过态）→ 分享卡片。这是产品价值脊柱，原型必须能让评审者一口气走通。

**Why this priority**：核心魔法流是产品全部价值所在，其余屏都是支撑。原型若只做一条，必做这条流。

**Independent Test**：打开原型首页，沿 `Count → 选图纸 → 拍照 → 结果 → 分享` 走完，能完整理解"拍一张 → 对照图纸 → 标出错豆 → 分享"。

**Acceptance Scenarios**：

1. **Given** 首页，**When** 点 `Count`，**Then** 进入选图纸（4 入口：相册 / 拍照 / 分享扩展 / 文件）。
2. **Given** 选定图纸，**When** 自动解析完成，**Then** 展示已解析图纸（马赛克预览）+ 尺寸（行列数）+ 颜色数 + **可选色盘** + **备豆统计（各色数量）**。
3. **Given** 已解析图纸，**When** 进入拍照并完成检测，**Then** 结果屏用**三种不同颜色**分别标注 颜色错 / 空缺 / 多余，并给出计数（如"3 处：2 颜色错 + 1 空缺"）。
4. **Given** 0 处差异，**Then** 结果屏显示"质检通过"通过态（净图，无标注）。
5. **Given** 结果页，**When** 点分享，**Then** 展示带品牌水印的分享卡片预览。

---

### User Story 2 - 状态与边界（Priority: P2）

描绘非 happy-path 状态，体现"魔法优先、不靠手动补救"哲学：解析中 / 解析低置信度（提示重选）/ 不支持场景（明确提示，无手动工具）/ 检测失败（重拍引导）/ 首启权限申请。

**Why this priority**：失败态决定"魔法流"可信度；首启权限是第一印象。优先级次于核心流，但影响信任。

**Independent Test**：能逐一查看每个边界态屏，确认"无手动校正 UI、只有重试 / 提示"。

**Acceptance Scenarios**：

1. **Given** 首次开 App，**When** 进入，**Then** 申请相机 / 相册权限（说明用途后请求）。
2. **Given** 解析低置信度，**Then** 温和提示"图纸不太清晰，建议重选 / 重截"（**无**手动框选工具）。
3. **Given** 反复失败，**Then** 识别为不支持场景并明确提示"这类图纸 / 拍摄场景暂不支持"（**不出现**手动逃生舱）。
4. **Given** 检测中，**Then** 展示进度（用户语言，不暴露检测流水线术语）。

---

### User Story 3 - 作品库与设置（Priority: P3）

描绘三屏信息架构的另两屏：作品库（作品列表 / 详情 / 重扫，体现自动保存）+ 设置（色盘品牌）。

**Why this priority**：补全信息架构，但非核心价值；可简略。

**Independent Test**：能看到作品列表（含自动保存的作品）、进入作品详情触发重扫、在设置切色盘。

**Acceptance Scenarios**：

1. **Given** 完成一次检测，**Then** 该作品自动出现在作品库（无需手动保存）。
2. **Given** 作品库，**When** 点作品 → 重扫，**Then** 跳过图纸直接进入拍照（图纸已随作品保留）。
3. **Given** 设置，**Then** 可切换色盘品牌。

---

### Edge Cases

- 空作品库（首次使用）的引导态如何展示？
- 大图（几百颗豆）错误多时，多色标记在结果图上是否仍清晰可读？
- 分享卡片在"通过"与"有错"两种结论下的视觉差异？
- 首启**拒绝**权限后的引导？

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**：原型 MUST 覆盖核心魔法流六屏（首页 / 选图纸 / 拍照 / 检测中 / 结果 / 分享）。
- **FR-002**：选图纸屏 MUST 展示：已解析图纸（马赛克预览）、尺寸（行列数）、颜色数、**可选色盘**、**备豆统计（各色数量）**。
- **FR-003**：结果屏 MUST 用**三种不同颜色**区分 颜色错 / 空缺 / 多余，并支持通过态（0 错 → "质检通过"，净图）。
- **FR-004**：原型 MUST 体现"无手动逃生舱"：所有失败 / 边界态只有"重试 / 不支持场景提示"，不出现手动校正工具。
- **FR-005**：原型 MUST 体现**自动保存**（检测完成 → 作品库），结果页无"保存"显式动作。
- **FR-006**：原型 MUST 含**首启权限态**（开 App 申请相机 / 相册）。
- **FR-007**：原型 MUST 沿用既有视觉方向（紫粉品牌渐变 / 暖白底 / 无 emoji / 结果页去边框 / `Count` 主按钮 / 去"AI 味"文案），参考 `docs/mockups/`。
- **FR-008**：原型 MUST 用用户语言（不出现检测流水线 / CV 术语），与 v1.4 PRD de-tech 一致。
- **FR-009**：产物 MUST 为浏览器可直接打开的 HTML，置于 `docs/mockups/`（**替换**既有旧稿，旧版由 git 历史保留），并提供 index 索引页串联各屏。
- **FR-010**：多色错误标记配色（取自既有色板）：颜色错 = `#EF4444`（红）、空缺 = `#38BDF8`（蓝）、多余 = `#F59E0B`（橙）；每处另配编号 + 字形，确保色弱可读。
- **FR-011**：原型为**静态视觉稿 + 屏间可点击导航**（index 索引页串联各屏，可点击跳转；无状态切换 / 动效）。
- **FR-012**：原型覆盖范围 = **核心魔法流六屏详细**（首页 / 选图纸 / 拍照 / 检测中 / 结果 / 分享）；**其余屏 / 态各一帧静态稿**（作品库列表、作品详情、设置、首启权限、解析低置信度、不支持场景、检测失败）。

### Key Entities *(include if feature involves data)*

- **Screen（屏）**：首页、选图纸、拍照、检测中、差异结果、分享卡片、作品库、作品详情、设置、首启权限。每屏含若干 State。
- **State（状态）**：如选图纸的「解析中 / 成功 / 低置信度 / 不支持场景」；结果的「有错 / 通过 / 检测失败」。
- **Artifact（产物）**：每屏 / 每态一个 HTML 文件 + 一个 index 索引页（串联导航）。
- **ErrorType（错误类型）**：颜色错 / 空缺 / 多余 —— 各对应一种标记色（见 FR-010）。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**：原型覆盖 v1.4 PRD 全部核心屏与关键状态，评审者可在 ≤5 分钟内沿索引走通完整魔法流。
- **SC-002**：每屏内容与 v1.4 PRD 一致，无遗漏（备豆统计、选色盘、多色标记、通过态、自动保存、首启权限、无逃生舱）—— 可逐项对照 PRD 核对。
- **SC-003**：视觉风格与既有 `docs/mockups/` 一致（品牌色、留白、文案调性），无明显割裂。
- **SC-004**：产物为浏览器可直接打开的 HTML，索引页可导航到每一屏 / 态。
- **SC-005**：多色错误标记在结果图上相互可区分，且不依赖单一颜色（配编号 / 字形，色弱可读）。

## Assumptions

- 产物为**静态 HTML 视觉稿**（参考 `docs/mockups/` 既有风格），非可运行的生产代码；用占位素材（豆子马赛克纹理）模拟成品照 / 图纸。
- 视觉沿用既有方向（代号 C：鲜亮活泼、克制），参考 `docs/superpowers/specs/2026-06-22-pintcount-prototype-design.md` 的设计令牌。
- 基于 v1.4 PRD；本次原型**迭代 / 取代** 2026-06-22 既有原型（因 PRD 已大幅修订：合并流、de-tech、备豆统计、选色盘、去逃生舱、自动保存、首启权限、多色标记）。
- 覆盖范围（已确认）：核心魔法流六屏详细，作品库 / 设置 / 边界态简略。
- 多色配色（已确认，取自既有色板）：颜色错 = `#EF4444`（红）、空缺 = `#38BDF8`（蓝）、多余 = `#F59E0B`（橙）。
- 不含真实检测 / 解析逻辑；所有"检测结果""备豆统计"为假数据。
- 平台基准沿用 iPhone 390pt（既有原型基准）。
